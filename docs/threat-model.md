# Threat model

Assets include generated plans (which can contain plaintext secrets), normalized snapshots, reports, approved baselines, suppression justifications, API keys and AWS credentials. A PR author controls infrastructure input and may try to hide a regression, overload analysis, or manipulate reports. Database/AWS outages and policy bugs can otherwise create false green checks.

The local default binds to loopback. Docker publishes loopback ports. Set `CHANGEGUARD_API_KEY` for shared use; every API/metrics request then needs `X-API-Key`, except health checks. This is a **single-tenant prototype**: any holder of the key can access all reviews and change baselines. Production deployment needs TLS, identity/authorization, separate rights to approve baselines/exceptions, request quotas, retention, audit identity, and network isolation for PostgreSQL/metrics. Do not expose the unconfigured API to an untrusted network.

Templates are data, never executed. CloudFormation macros/intrinsics are not evaluated, Terraform is never invoked on the server, and AWS endpoints are fixed SDK endpoints. Unknown checks and unsupported resources fail closed. Clients cannot suppress rule errors or destructive stateful changes. Reports omit raw property values; stored snapshots retain them for baseline analysis. Restrict database backups and artifact access accordingly. Markdown escapes HTML/control characters and common formatting characters.

Application limits are 10 MB per template, 10,000 normalized resources, and 1,000 exceptions. The HTTP filter rejects declared bodies over 22 MB. A production reverse proxy must enforce the actual streamed body limit, connection timeouts and rate limits; Content-Length checks alone do not bound chunked bodies. Cache capacity is by entries, not bytes; very large resource properties can consume substantial memory. Bound process/container memory and trusted rule count.

GitHub uses `pull_request` with read-only repository permissions, a disposable local service, and no cloud secrets. The example workflow scans a fixture; workload repositories must scan their generated deployment artifact and protect the workflow/rules with branch protection/CODEOWNERS. Never run untrusted PR code using `pull_request_target` and privileged credentials. The Actions job is the check; no outbound PR comments are needed.

Database transactions and advisory locks prevent partially persisted/duplicate reviews. Rule errors and AWS failures do not manufacture success; AWS context availability is separate from a static gate. AWS integration is disabled by default and uses the SDK credential chain, so no credentials are embedded in the project. Configure least-privilege Well-Architected API permissions for authorized workload ARNs when enabling it.
